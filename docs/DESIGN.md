# ClearNote interface

The default native window width is 678 DIPs, with 12-DIP outer side gutters around the reading column and a matching 12-DIP bottom gutter. The bottom gutter is outside the scrolling feed. Width stays fixed between changes made through the Wider and Narrower menu actions; height remains resizable. The chosen width is remembered in Log/window.json. Each action applies a complete small step, without showing a percentage. Limits disable the action rather than partially resizing. The maximize action is removed. Startup reduces dimensions only to fit a smaller work area. All data remains under the executable's Log folder.

The header has two compact aligned groups: Notes, Review and Memo on the left, magnifying-glass and overflow icons on the right. Search opens a compact popup and filters the active collection. Review opens a Notes-only tag menu anchored to its button; there is no inline tag selector. Opening or dismissing it leaves the current feed unchanged. The top composer posts into the vertical feed using a borderless Post text button with a quiet slate label. Composer and notes share the column edges and fine horizontal separators, with no rounded outer card outlines or gaps. Side lines continue through the twelve-DIP bottom gutter. Body text is 16 DIPs with a 21-DIP line height, two-DIP paragraph gaps, no final paragraph gap in the read-only display, and twelve-DIP note bottom padding.

The title-bar icon opens a compact native window menu. A normal window offers Move, Resize height, Minimize and Close; the height action starts native bottom-edge resizing while retaining the reading width. Restore appears when it has an effect, including in the minimized state. Maximize is omitted because it conflicts with the fixed reading column. Native Close and Alt+F4 retain normal draft-save and pending-import guards.

Consolas and FangSong retain their separate Latin and Chinese mappings. The window, feed, composer, attachment frames and menus use pure white backgrounds. A shared ContentRegion style turns the hovered composer or whole note to #F7F7F7, including its text area. Editor and FlowDocument backgrounds are transparent; explicit user highlights and picture pixels remain intact. Automatic text is #0F1419; secondary text and action strokes are #536471. Hover uses background fill rather than reducing text or icon opacity. The ClearNote mark is a contemplative black-and-white alien silhouette with an elongated head, white almond eyes and a hand beneath its chin. It uses no enclosing tile, text, color or gradient. SVG, multiresolution ICO, the executable icon and the default avatar share the same geometry. Buttons are borderless. Padded 13-DIP menu labels have edit/delete line icons and a generous hit area inside a rounded white menu. No gradients or dark logo tile are used.

Double-clicking read-only note content enters its independent inline editor, including in Review. Short edits use their natural content height; longer edits grow to 420 DIPs and then scroll internally. Double-clicks on buttons or an active editor retain their native behavior. Editing and saving do not count another review. Switching modes or tags first attempts to save open edits; a failed save leaves the editor and filter intact. At a paragraph start, a typed space after a positive integer, such as `1. `, starts a native ordered list. Both text input and WPF's native Space command are handled, including typing queued before an immediate save or Return. Pasted bare numbers and numbers inside existing list items remain literal. Native undo groups conversion into one step. Return creates a paragraph; Shift+Return creates a line break within the same paragraph or list item. Stored line breaks are reconstructed as native LineBreak elements on reload.

Each note has a 42-DIP circular avatar and the local author name above its date. The avatar supports a keyboard-accessible profile button and a right-click menu for editing the profile or choosing a picture. Profile settings also remain available in the overflow menu. A single current profile applies across the library; it is separate from card contents and review state. A durable profile save updates identity elements in place, preserving active edits, composer drafts, scroll position and review-session tracking. Profile persistence belongs to Core, picture selection and the dialog belong to App, and FeedView only distributes the identity to its rendered cards.

WelcomeNotes creates two ordinary CardDocuments only after Core has successfully loaded a library without a saved collection. The text-only introduction has one bold opening line and a brief account of capture, spaced review and offline ownership. It appears above a second post containing a short caption and a landscape. Both use the normal You identity and default avatar; neither has a special rendering or deletion path. The embedded landscape passes through the normal image importer into Log/Data/assets. InitializeNewLibrary commits the two posts together. An existing saved library, including one deliberately emptied by the user or restored empty, is never seeded again.

Attachments are independent of the native text buffer. The composer and each inline editor own a separate image list. Read-only pictures use a horizontal gallery with an 8-DIP gap and a common 308-DIP height, ten percent above the former height limit. Width follows each picture's aspect ratio, independent of attachment count or column width. Draft previews use a common 184.8-DIP height. Circular Previous/Next controls, keyboard navigation and Shift+wheel move through overflowing pictures without consuming ordinary vertical feed scrolling; a single panorama can also be paged without skipping its middle. A whole file selection is decoded before assets are imported, and a replacement attachment view is built before committing editor state. Images become durable assets before a draft or note references them. A rejected import or save retains existing edits; cancel restores the saved text and attachments.

Notes and Memo are independent collections in one library, sharing assets and identity but keeping separate draft files and recovery state. An omitted collection field reads as Notes for compatibility. Collection membership is validated and immutable after posting. Memo has the same feed controls but is excluded both from the Review UI and from Core scheduler selection and review updates. Switching collections saves open edits and the outgoing draft before binding the destination; a failed save leaves the original view intact. Backups and restore retain both collections and drafts, and deletion considers image references across both streams and their recoverable drafts. The focused LibraryStore.Drafts partial owns draft persistence and per-collection conflict detection.

Image import captures paste data on the UI thread and performs encoded-file decoding, validation and asset creation in the background. Strictly validated normal-orientation PNG/JPEG files retain their encoded bytes and full resolution. Readable source containers rejected by the portable-asset validator are normalized automatically from decoded pixels; other codecs and rotated images also become normalized PNG copies using native Windows imaging transforms. Previews are detached Bgra32 surfaces at 96 DPI and use a bounded frozen cache. PNG byte and stream paste data precedes bitmap paste to retain alpha, with a detached Bitmap fallback when that PNG representation is unusable. Clipboard surfaces are copied while their provider is available. A converted PNG that exceeds the 20 MiB asset limit is rescaled proportionally by 0.8 on each attempt, leaving the source file intact. Source byte and pixel limits remain enforced before conversion. Optional formats depend on Windows codec availability.

Import failures have actionable English messages for decode errors, limits, missing or locked files, insufficient disk space and access failures. The status tooltip includes the error code and diagnostic path when available. Only failures create bounded daily logs under Log/Diagnostics; a logging failure never replaces the original operation error or blocks editing.

Deleting a note removes it from the active collection and the previous library save, then deletes its exclusively owned local image assets. Other notes, the current profile, and current or previous recoverable drafts retain their referenced images. The deletion journal contains only the target ID and asset names, and lets startup finish interrupted work without resurrecting the removed post. Source image paths are never deletion targets. Closing or deleting content creates no automatic archive; explicit backup and the safety snapshot before restoring remain available.

Hashtags remain visible text. Existing-tag completion preserves the editor's focus and native undo history. A hash followed by a space keeps its Markdown heading meaning. Review filtering occurs before scheduling and batching, while the session's recorded IDs stay intact across tag changes.

The native text editor remains responsible for selection, paragraphs, undo and lists. Media decoding and import belong to ImageAttachments; AttachmentPanel renders references; NoteTags derives searchable labels. These boundaries avoid introducing image objects into the rich-text document or coupling review history to feed snapshots.

The dependency direction is App to Core. Core contains no WPF dependency; each check project targets its own layer. LibraryStore.Drafts, LibraryStore.Profiles and LibraryStore.Deletion keep focused persistence concerns together. MainWindow.Width owns width actions and native sizing; WindowWidthPreferences owns presentation settings. Welcome creation remains an App concern because its embedded picture needs the Windows image decoder. Core provides the one-time initialization transaction.

Startup uses the active monitor work area, leaving 12 DIPs above and below the native window. The taskbar remains available, the reading width stays fixed, and the user can still resize the height.
